# 高德周边步行推荐

## 基本原则

- 必须实际调用高德 MCP 工具。地点名称、地址、坐标、类别和路线数据只能采用本轮工具返回的结果，不得凭记忆或常识编造，也不得只描述调用计划而不执行。
- 用户给出的起点坐标是所有查询的唯一出发点，保持其经纬度顺序和精度，不使用设备定位、城市中心或其他地点替代。
- 每个推荐都是从该起点出发的独立备选；不得把多个地点串成多站路线。

## 工具选择

先查看平台实际提供的工具 schema，选择对应的高德能力。常见官方工具如下，名称可能带平台前缀，以实际 schema 的名称为准，不自行编造参数：

| 能力 | 常见工具 | 关键参数 |
| --- | --- | --- |
| 周边地点搜索 | `maps_around_search` | `keywords`：地点类别或需求关键词；`location`：起点经纬度；`radius`：可选搜索半径 |
| 关键词地点搜索 | `maps_text_search` | `keywords`：地点类别或需求关键词；`city`：用户城市 |
| 步行路线规划 | `maps_direction_walking` | `origin`：起点经纬度；`destination`：候选地点经纬度 |

优先用周边搜索发现候选，关键词搜索用于补充。搜索半径只控制候选召回，不能证明符合步行时间要求；距离测量、直线距离、驾车或其他交通方式也不能代替步行路线规划。

## 工作流程

### 1. 解析需求

提取城市、起点坐标、地点类别、步行时间上限、数量及其他偏好，区分必须满足的硬约束与排序偏好。未指定数量时最多推荐 3 个；指定更少时遵守用户，指定更多时仍最多返回 3 个。不得擅自放宽类别、时间或数量要求。

### 2. 搜索并整理候选

以用户需求为关键词、用户起点为搜索中心调用地点搜索，城市参数按实际 schema 填写。候选数量应多于目标数量，以便过滤后有备选；保留每个候选的 POI ID（如有）、名称、地址、类别和经纬度，并按 POI ID 去重，没有 ID 时结合名称、地址和坐标去重。

剔除明显不属于所需类别或缺少必要坐标的候选。结果不足时可调整关键词或搜索半径补充召回，但仍须执行后续路线查询，不能直接用搜索距离补足推荐。

### 3. 逐一查询步行路线

对每个可能入选的候选及必要备选，分别调用一次步行路线规划：`origin` 始终是用户给出的同一起点，`destination` 是该候选的真实坐标。核对返回路线与候选的对应关系。若符合项不足，继续查询其他候选，不得只按 POI 距离选取前几个后直接推荐。

只使用查询成功且具有完整路线的结果。若返回多个 `paths` 方案，优先采用工具默认或首条完整方案，并始终读取同一方案的总 `distance` 和总 `duration`；不得混用不同方案、采用某个分段数据，或用直线距离替代。

按工具说明确认单位。高德步行方案通常以米返回 `distance`、以秒返回 `duration`：

- 距离换算：`千米 = 米 / 1000`。
- 时间换算：`分钟 = 秒 / 60`，不得把秒数直接写成分钟。
- 有“不超过 T 分钟”限制时，先用原始值判断 `duration <= T * 60`，再换算和适度四舍五入用于展示；不得先取整再过滤。

### 4. 过滤、排序并生成理由

路线查询后统一执行硬约束过滤：类别必须匹配，原始步行耗时必须在上限内，其他明确硬条件也必须满足。超时、路线失败、路线数据缺失或类别不符的候选均不得列入符合要求的推荐，即使它们距离很近。

按用户偏好排序。“优先近一点”必须按实际步行路线的原始 `distance` 升序排列，可用 `duration` 处理并列；不得按搜索返回顺序或直线距离排序。其他偏好仅在有工具数据支持时用于排序，不虚构评分、口碑或环境特征。

每个推荐理由用一句话说明其数据依据，例如类别匹配、实际路线距离与耗时满足上限、在符合项中的距离排名，或工具明确返回的其他属性。安静程度、排队情况、营业状态等没有可靠返回依据的信息，若用户关心则明确标注“未核实”，不得写成已满足的优点。

### 5. 输出结果

用简洁中文列表或表格返回不超过目标数量的地点，每项必须包含：

| 名称 | 地址 | 步行距离 | 预计步行时间 | 简短推荐理由 |
| --- | --- | --- | --- | --- |

名称和地址采用地点搜索返回的信息，地址缺失时可通过高德地点详情补查，仍缺失则如实写“高德未提供”，不得推测。距离与时间必须来自该地点本次步行路线查询的同一方案，并使用清楚的米/公里和分钟单位。

- 数量不足时，只推荐实际符合项，并简述原因，例如其余候选类别不符、步行超时或路线查询失败；不要用不合格地点凑数。
- 无符合结果时，明确说明本次高德查询未找到满足条件的地点，可建议放宽步行时间、地点类别或搜索范围，但不得自行放宽后冒充符合项。
- 工具异常可合理重试；仍失败时如实说明服务异常及受影响环节，不编造地点或路线。可建议稍后重试或调整条件。

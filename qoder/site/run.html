运行与验证说明

按本页说明在自己的环境运行应用并验证真实写入与召回。展示站不承载应用后端；服务地址和凭据由运行者配置。

环境要求 配置 启动与停止 真实 HTTP 验证 验证样例

环境要求

  • Python 3.11 或更高版本（应用只用标准库，没有 pip 依赖）。
  • 一个可访问的 PowerContext 服务，OpenAPI 版本 v1.2.0，能力包含 /v1/memory/remember、/v1/context/prepare、/v1/memory/entries/list。
  • bash 与 curl（可选，用于演示脚本）。
git clone --branch qoder-solution https://github.com/zhangxh0526/powercontext.git
cd powercontext/qoder
python3 --version    # 需要 >= 3.11

配置

复制配置示例并按自己的环境填写。示例文件不含任何真实凭据。

cp config.example.env .env   # .env 已在 .gitignore 中
配置项
变量必填说明
POWERCONTEXT_URL是 PowerContext 服务地址，必须是 http 或 https URL。未设置时使用 http://127.0.0.1:8000。
POWERCONTEXT_TOKEN否 服务启用鉴权时设置。只作为请求头发送，绝不写入日志、证据或页面。
POWERCONTEXT_SCOPE否 仅可作为"默认实验"的 Scope 复用来源。留空时每个实验都会创建并持久保存自己的 Scope；不会让所有实验共用一个 Scope。
ASSISTANT_HOST / ASSISTANT_PORT否 应用监听地址与端口，默认 127.0.0.1:8710。
ASSISTANT_DATA_DIR否 实验与 Scope 映射目录，默认项目下的 data/，还包含保存时的表单元数据。召回始终读取 PowerContext。

启动与停止

前台启动

cd powercontext/qoder
export POWERCONTEXT_URL='http://127.0.0.1:8000'  # 改为已有服务的地址
python3 -m backend.server
# 浏览器打开 http://127.0.0.1:8710/，Ctrl-C 停止

后台服务脚本

未导出 POWERCONTEXT_URL 时读取本地 .env；已导出时使用完整的进程环境配置。

./scripts/dev-server.sh start     # 启动并等待 /api/health 就绪
./scripts/dev-server.sh status    # 查看进程与健康状态
./scripts/dev-server.sh logs 50   # 查看最近 50 行日志
./scripts/dev-server.sh restart   # 重启（用于验证重启恢复）
./scripts/dev-server.sh stop      # 停止

pid 记录在 runtime/dev-server.pid，日志在 runtime/dev-server.log，两者都被忽略提交。

真实 HTTP 验证

三个脚本都自行启动应用、发送真实 HTTP 请求、断言结果，并在失败时以非零状态退出；请求与响应写入 evidence/。只用命令行，不涉及浏览器自动化。

export POWERCONTEXT_URL='http://127.0.0.1:8000'  # 改为已有服务的地址

python3 verify_powercontext.py                  # 独立验证服务本身的写入与召回
python3 verification/verify_app.py              # 应用主流程：空状态、写入、召回、隔离、重启恢复、错误状态
python3 verification/verify_save_order.py       # 连续保存回归：最新一次成功保存必须被召回
python3 verification/verify_text_roundtrip.py   # 文本往返回归：分号/字段名/引号/HTML/换行逐字一致

./scripts/dev-server.sh start
python3 scripts/demo-run.py                     # 端到端演示：创建→保存→召回→重启进程→再召回

页面交互与截图由项目验收方在自己的浏览器中完成，结果保存在 evidence/browser-ui-20261030/。

操作步骤与预期结果

  1. 创建实验 → 后端调用 POST /v1/scopes 为该实验创建独立 Scope 并持久保存映射。
  2. 保存进展 → 后端调用真实 POST /v1/memory/remember（kind=decision），响应返回 entry.citation 中的真实 entry ID 与 entry version ID。
  3. 召回 → 后端调用 POST /v1/context/prepare（锚点 实验进展 + 实验名称 + 用户问题），并用同一 Scope 的记忆清单补全被截断的候选；页面显示实验名称、进展、下一步与真实 entry 身份。
  4. 停止并重启应用进程（数据目录与 Scope 不变）→ 再次召回应恢复到同一条 entry，进展与下一步逐字一致。
  5. 预期：进展与下一步与输入逐字相同，HTML 标签按字面显示，state=recalled；无记忆、服务不可用与接口错误分别显示。
